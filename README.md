<h1 align="center">Triage Bot</h1>

<p align="center">
  Фильтр рабочих чатов на базе Gemini: читает сотни сообщений в день и присылает только то, что реально важно.
</p>

---

## Зачем это

Человек, у которого работа завязана на кучу рабочих Telegram-чатов (учитель, менеджер, кто угодно с десятком групповых чатов), физически не может прочитать всё — но боится пропустить то единственное сообщение, которое его касается. Обычно решение — сидеть и вручную листать всё подряд, тратя на это часы в день.

Этот бот решает задачу иначе: сам читает все чаты через Telegram-аккаунт пользователя, прогоняет сообщения через Gemini и присылает уведомление **только** по-настоящему важным вещам — с прямой ссылкой на сообщение или пересылкой оригинала. Всё остальное тихо архивируется и один раз в день собирается в короткий пересказ дня.

## Что умеет

- **Приватный выбор чатов** — бот читает только те чаты, которые ему явно разрешили, ничего лишнего
- **Три уровня приоритета** — часть сообщений (прямой реплай/упоминание/личка) считаются важными мгновенно и без ИИ; часть эскалируется на одиночный запрос вне очереди (по ключевым словам вроде "срочно", "сегодня"); остальное копится и разбирается пачкой раз в N минут — экономит и деньги, и время
- **Голосовые сообщения** — распознаются в текст и разбираются как обычные сообщения
- **Вложения** — фото и файлы анализируются моделью по содержимому, не только по названию
- **Склейка обрывков** — если человек пишет мыслями по одному слову в разных сообщениях, бот сам их объединяет перед анализом
- **Приоритетные правила** — можно явно сказать "экскурсия 10Б — это важно" с указанием срока действия и области (конкретная группа чатов или все разом)
- **Дневная сводка** — раз в день короткий пересказ того, что вообще происходило в каждом чате, с однотипными репликами (да/нет/буду), схлопнутыми в одну фразу
- **Два бота** — один только для настройки, второй только для уведомлений, чтобы не путать интерфейс с пушами
- **Устойчивость к сбоям** — переподключение при обрыве связи, ротация нескольких ключей Gemini, аварийное добавление новых ключей прямо через бота
- **Авторизация через сам бот** — не нужен доступ к серверу, чтобы подключить свой Telegram-аккаунт

## Как это устроено

```
Telegram-аккаунт (Telethon userbot)
        │
        ▼
  adapters/telegram.py  ──> нормализует события в единый формат
        │
        ▼
  core/prefilter.py  ──> мгновенно / вне очереди / в общий поток
        │
        ▼
  core/classifier.py  ──> Gemini: важно или нет (с учётом профиля и правил)
        │
        ▼
  core/notify.py  ──> алерт-бот: ссылка на сообщение или пересылка оригинала
```

Два отдельных Telegram-бота (aiogram) и один Telethon-клиент (человеческий аккаунт, не Bot API — только так можно читать групповые чаты как участник). БД — SQLite, её вполне достаточно для одного человека.

Архитектура заранее рассчитана на несколько источников — `adapters/base.py` описывает контракт, которому должен соответствовать любой адаптер, так что Пачка/Gmail/Яндекс.Почта подключаются без переделки остального пайплайна.

## Технологии

Python 3.12 · aiogram 3 · Telethon · SQLAlchemy (async) + SQLite · Google Gemini API

## Быстрый старт

### 1. Клонировать и поставить зависимости

```bash
git clone <ссылка-на-твой-репозиторий>
cd triage-bot
python3.12 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Получить учётные данные

- **TG_API_ID / TG_API_HASH** — на [my.telegram.org](https://my.telegram.org) → API development tools
- **TG_BOT_TOKEN** и **TG_ALERT_BOT_TOKEN** — два отдельных бота через [@BotFather](https://t.me/BotFather) (`/newbot`)
- **GEMINI_API_KEY** — на [aistudio.google.com](https://aistudio.google.com/apikey); можно указать несколько ключей через запятую, они крутятся по кругу

### 3. Настроить `.env`

```bash
cp .env.example .env
```

Заполни значениями из шага 2. `ALLOWED_TG_USER_IDS` — telegram user_id всех, кому разрешено пользоваться ботами (свой узнать у [@userinfobot](https://t.me/userinfobot)), через запятую без пробелов.

### 4. Запустить

```bash
python main.py
```

### 5. Авторизовать чтение чатов

В settings-боте:

```
/login
```

Бот спросит номер телефона, потом код из Telegram (и пароль, если включена двухфакторка) — прямо в диалоге, доступ к серверу не нужен.

### 6. Настроить, что мониторить

```
/chats      — выбрать чаты
/profile    — пара слов о себе
```

В alert-боте — один раз `/start`, чтобы бот знал, куда слать уведомления.

## Команды

| Команда | Что делает |
|---|---|
| `/login` | Авторизовать чтение чатов (диалог прямо в боте) |
| `/platform` | Выбрать платформу, к которой применяются настройки |
| `/chats` | Выбрать чаты для мониторинга |
| `/find текст` | Найти чат по названию |
| `/monitored` | Снять мониторинг с чата |
| `/tag текст` | Присвоить группу-тег части чатов |
| `/tags` | Показать все группы и что в них входит |
| `/profile [текст]` | Посмотреть/изменить описание себя |
| `/add_rule текст` | Добавить приоритетное правило |
| `/rules` | Список активных правил |
| `/stats` | Сводка за сегодня |
| `/settings` | Интервал разбора, час и вкл/выкл дневной сводки |
| `/api ключ1,ключ2` | Добавить резервные ключи Gemini на лету |
| `/fresh`, `/daily` | Принудительно прогнать разбор/сводку (для тестов) |

## Структура проекта

```
adapters/       — контракт источника + реализация для Telegram (Telethon)
bot/            — обработчики settings- и alert-бота (aiogram)
core/           — вся логика: prefilter, classifier, listener, scheduler, digest
db/             — модели SQLAlchemy и подключение к БД
scripts/        — резервный способ авторизации через консоль
main.py         — точка входа, поднимает оба бота и фоновые задачи
```

## Приватность

Бот читает только те чаты, которые ему явно разрешили через `/chats` — остальные сообщения физически не попадают ни в БД, ни в ИИ. Telethon-сессия (`*.session`) — это полноценный доступ к Telegram-аккаунту, `.env` — все токены и ключи; оба уже в `.gitignore` и никогда не должны попадать в репозиторий.
